# Contributing

Thank you for helping. These defaults apply to every repository of the
organization that does not bring its own `CONTRIBUTING.md`.

## Issues

- Search the open issues first and extend an existing one instead of opening a
  duplicate.
- Use one of the issue forms. Each issue covers one independently mergeable
  piece of work and states its goal, context and evidence, scope, what is out
  of scope, acceptance criteria and the production evidence.
- Name the milestone and any blocking or blocked issues in the form.

## Pull requests

- Link the issue the change closes and keep the change focused on it.
- Use a Conventional Commit for every commit message and for the pull request
  title, for example `fix: handle an empty response`.
- Run the repository's checks locally before pushing and report their results,
  including any you could not run, in the pull request.
- Cover changed behaviour with tests and update the documentation it affects.
- Write code identifiers, comments, commit messages and documentation in
  English.

## Security

Do not report vulnerabilities in issues or pull requests. Follow the
[security policy](SECURITY.md).

## Licence

Unless a repository states otherwise, contributions are made under that
repository's licence.
